# 入境旅游服务标准互认

管理入境旅游服务标准、认证证据和跨境互认标识。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括东盟旅行社、国内景区、支付机构、接待企业、行业协会、认证机构与旅游主管部门。

资料所依据的领域事实如下：

- 便利化活动探索入境旅游服务标准化发展路径
- 参会方来自主管部门、东盟行业协会、金融机构和文旅企业
- 跨境支付与数字文旅属于核心议题
- 服务标识按适用地区和有效期限限定范围，不与各企业自我声明混同
- 主管部门能够区分自我声明、第三方认证与正式互认
- 标准修订、认证暂停、抽查不合格、机构退出或跨境关系撤销时，在售产品必须准确更新

## 资料结构

- `service_items`：标识可覆盖的服务项目（多语种接待、支付帮助、应急联络）。
- `regions` 与 `regional_profiles`：适用地区，以及按地区关联的服务条款、语言版本、证据要求与认证机构。
- `recognition_levels`：自我声明、第三方认证、正式互认，按核验严格程度排序。
- `standards`：标准版本及其状态（现行、已被替代、草案）。
- `certification_bodies`：认证机构及其状态（正常、暂停、退出）。
- `marks`：在售产品上的有限范围标识，注明服务项目、适用地区、有效期限、认定等级与标准版本；供应商提交对应版本材料后方可获得。
- `verification_records`：自我声明、第三方核验与现场核验记录，逐条注明责任主体。
- `change_events`：标准修订、认证暂停、抽查不合格、机构退出、跨境关系撤销等变更事件及其影响范围。

## 读取与查询

`src/domain.py` 负责校验资料的结构与引用完整性（等级必须有相应核验支撑、每个标识都能追到核验记录与责任主体），并提供：

- `mark_scope`：标识对游客展示的服务项目、适用地区与有效时间；
- `trace_mark`：从原标识追到核验记录与责任主体；
- `affected_marks`：变更事件发生后需要准确更新的在售标识；
- `supplier_gap`：企业达到目标认定等级还缺的证据与核验，作为整改依据；
- `recognition_rank`：认定等级排序，供主管部门区分自我声明、第三方认证与正式互认。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束与结构化栏目。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
